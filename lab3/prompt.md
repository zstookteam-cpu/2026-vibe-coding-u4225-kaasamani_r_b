## Исходный запрос и согласование плана

**Запрос пользователя:**
> Выполнить лабораторную 3. Хостинг делаем через Railway.

**Ответ LLM (план):** деплой воркера на Railway (polling, а не webhook — не нужен публичный домен),
база SQLite на Volume, переменные окружения вместо `.env`; в бота добавить опрос `/feedback`, учёт
использования команд и админские `/stats`, `/feedbacks`; собрать отзывы ≥ 3 реальных пользователей,
проанализировать и внести улучшения.

**Решение пользователя:** аккаунт Railway есть; администратор — Telegram ID 280147464;
локальный бот на время работы Railway останавливается (один токен — один экземпляр).

## Промпт по шаблону курса

```
Доработай Telegram-бота-ассистента для задач (Python, python-telegram-bot 21.6, SQLite, JobQueue, Open-Meteo)
для запуска на хостинге Railway и сбора обратной связи.

Требования к деплою:
- конфигурация только через переменные окружения: BOT_TOKEN, ADMIN_ID, TIMEZONE, DB_PATH, необязательно PROXY_URL;
- путь к SQLite задаётся DB_PATH (каталог создаётся автоматически) — база лежит на Volume Railway;
- режим polling, процесс-воркер (Procfile: worker: python -u bot.py), railway.json с перезапуском при падении;
- ограничить рост кэша погоды в памяти.

Обратная связь:
- /feedback — диалог (ConversationHandler): оценка 1–5 кнопками, затем «что понравилось», «что не понравилось»,
  «что улучшить» (ответ «-» пропускает вопрос), «будете ли пользоваться» кнопками; /cancel отменяет опрос;
  таймаут диалога 30 минут; устаревшие кнопки не должны ломать бота;
- отзывы сохранять в таблицу feedback; новый отзыв пересылать администратору;
- логировать использование команд в таблицу events (сбой записи не должен ломать бота);
- /stats (только ADMIN_ID): число пользователей, активность за 24 часа и 7 дней, популярные команды,
  задачи созданы/выполнены, число отзывов, средняя оценка;
- /feedbacks (только ADMIN_ID): последние 10 отзывов;
- команды администратора показывать в меню только ему (BotCommandScopeChat).

Не ломать функционал Лаб. 1–2. Комментарии на русском. Добавь автотесты для новых функций.
```

## Итерация 2 — улучшения по отзывам пользователей

**Исходные данные:** 4 реальных отзыва из `/feedbacks` (оценки 5, 5, 3, 5).
Повторяющиеся запросы: «погода не нужна» (1), «график продуктивности» (1), «всё в календаре» (1),
«план на неделю: сегодня / завтра / на неделе / потом» (1), «ежедневные задачи» (1).

**Решение пользователя:** план улучшений согласован — реализовать все пять пунктов.

```
Доработай бота по отзывам пользователей (python-telegram-bot 21.6, SQLite). Не ломай существующее.

1. Погода по желанию: в /start, /help и /today не навязывать город; без города /today не упоминает погоду;
   /city off отключает погоду.
2. /progress: выполненные задачи за 7 дней по дням (текстовый столбик ████░░), доля выполненных,
   серия дней подряд (до сегодня или до вчера).
3. /calendar: отправить файл tasks.ics (RFC 5545) со всеми активными задачами, у которых есть напоминание;
   экранирование и перенос длинных строк, ежедневные — с RRULE:FREQ=DAILY.
4. /plan: активные задачи по группам — сегодня (включая просроченные напоминания), завтра, на неделе (до 7 дней),
   потом, без срока; внутри группы — по времени и приоритету.
5. Ежедневные задачи: /remind <номер> daily <ЧЧ:ММ>; после напоминания следующее назначается автоматически;
   /done отмечает выполнение за день (копия в выполненных, чтобы работали /progress и серия), задача остаётся;
   /unremind и обычный /remind отключают повтор. Миграция SQLite: колонка repeat без потери данных.

Добавь автотесты на всё перечисленное (в т.ч. миграцию старой базы). Комментарии на русском.
```
